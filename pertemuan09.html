1. Konsep Dasar Routing & Forwarding

Peran Router, Control Plane vs Data Plane, dan Struktur Routing Table

Anatomi Router & Forwarding Paket

Router adalah perangkat Layer 3 (Network Layer) yang menghubungkan dua atau lebih subnet/jaringan yang berbeda.

Dua Fungsi Kunci Network Layer:
1. Routing (Control Plane): Proses menentukan rute/jalur terbaik dari sumber ke tujuan.
2. Forwarding (Data Plane): Proses fisik memindahkan paket dari interface input ke interface output yang tepat.

Router mengambil keputusan penerusan berdasarkan informasi yang tercantum dalam Routing Table (Tabel Penerusan).

Ilustrasi keputusan forwarding paket di dalam router
Jelaskan perbedaan mendasar: Routing itu membuat petanya (control plane), sedangkan forwarding adalah tindakan fisik belok kiri/kanan berdasarkan peta tersebut (data plane).

Struktur Routing Table

Routing Table berisi daftar jaringan tujuan yang diketahui oleh router beserta jalur untuk mencapainya. Contoh tampilan routing table pada Cisco IOS (show ip route):

Gateway of last resort is 192.168.1.1 to network 0.0.0.0 C 192.168.1.0/24 is directly connected, GigabitEthernet0/0 L 192.168.1.254/32 is directly connected, GigabitEthernet0/0 S 10.10.0.0/16 [1/0] via 192.168.1.2 O 172.16.0.0/16 [110/2] via 192.168.1.3, GigabitEthernet0/0 S* 0.0.0.0/0 [1/0] via 192.168.1.1
Arti Kode Protokol:
• C = Connected (Terhubung langsung)
• S = Static Route (Rute manual)
• O = OSPF, R = RIP, B = BGP
Format Nilai dalam Kurung [AD / Metrik]:
• Nilai pertama = Administrative Distance (AD)
• Nilai kedua = Metric (biaya/jarak ke tujuan)
Ajak mahasiswa membaca output 'show ip route'. Tekankan arti angka di dalam tanda kurung kurawal siku [110/2] yang sering kali membingungkan pemula.

Administrative Distance (AD) & Metrik

Administrative Distance (AD)

Tingkat kepercayaan (trustworthiness) dari sumber rute. Jika router menerima informasi tujuan yang sama dari protokol berbeda, nilai AD terkecil yang dipilih masuk ke routing table.

Sumber Rute Nilai AD
Connected Interface 0 (Paling Dipercaya)
Static Route 1
eBGP (External BGP) 20
OSPF 110
RIP 120
iBGP (Internal BGP) 200

Metric (Metrik Rute)

Nilai kuantitatif yang digunakan oleh protokol yang sama untuk memilih jalur terbaik jika terdapat beberapa jalur alternatif.

Metrik per Protokol:
• RIP: Hop count (jumlah router perantara).
• OSPF: Cost (berdasarkan bandwidth link).
• BGP: BGP Path Attributes (AS-Path, Local Pref, MED).
Prinsip: AD menentukan protokol mana yang menang, sedangkan Metrik menentukan jalur mana yang menang di dalam satu protokol.
Tekankan: AD membandingkan antar protokol (Static vs OSPF vs RIP). Metrik membandingkan jalur di dalam satu protokol yang sama (OSPF jalur A vs OSPF jalur B).

Prinsip Longest Prefix Match (LPM)

Ketika router menerima paket IP, router akan mencocokkan IP tujuan paket dengan semua rute di Routing Table. Aturan pemilihannya: Rute dengan subnet mask paling panjang (paling spesifik) yang akan dipilih.

Studi Kasus: Paket datang dengan alamat IP tujuan: 192.168.1.150.
Terdapat 3 rute yang cocok di Routing Table:
Rute di Routing Table Prefix Length Next Hop Keputusan Router
0.0.0.0/0 (Default Route) 0 bit 10.0.0.1 Cocok (tetapi paling umum)
192.168.0.0/16 16 bit 10.0.0.2 Cocok (lebih spesifik)
192.168.1.128/25 25 bit 10.0.0.3 DIPILIH (Longest Match / Paling Spesifik)

Karena /25 memiliki bit paling panjang yang cocok dengan 192.168.1.150, paket diteruskan ke 10.0.0.3, mengabaikan rute /16 dan /0.

Longest Prefix Match adalah algoritma perangkat keras inti router. Ingatkan mahasiswa bahwa /32 adalah host route (paling spesifik), sedangkan /0 adalah default route (paling umum).

2. Routing Statis (Static Routing)

Rute Manual, Gateway of Last Resort, dan Redundansi Floating Static

Karakteristik Routing Statis

Kelebihan Routing Statis
  • Efisiensi Sumber Daya: Tidak membebani CPU dan RAM router karena tidak ada proses kalkulasi algoritma.
  • Bebas Overhead Bandwidth: Tidak ada pertukaran paket update rute di jaringan.
  • Keamanan Terjamin: Administrator memegang kendali penuh. Tidak ada risiko pemalsuan rute (route spoofing).
  • Prediktabilitas Tinggi: Rute selalu pasti dan tidak berubah-ubah.
Kekurangan Routing Statis
  • Konfigurasi Manual: Sangat melelahkan pada jaringan berskala menengah hingga besar (N × (N-1) entri).
  • Tidak Adaptif (Tidak Ada Failover Otomatis): Jika kabel atau router perantara putus, router tidak dapat mengalihkan rute secara otomatis.
  • Rentan Human Error: Kesalahan ketik satu digit IP atau netmask menyebabkan paket terputus (blackhole).
Use Case Terbaik: Jaringan kecil (SOHO), Stub Network (jaringan dengan hanya satu jalur keluar/masuk), rute cadangan (Floating Static), dan rute default menuju ISP.
Tekankan bahwa routing statis sangat baik untuk jaringan berskala kecil atau ujung (stub), namun menjadi mimpi buruk operasional jika diterapkan pada ISP atau enterprise besar.

Konfigurasi Routing Statis

(Cisco IOS)

Perintah dasar konfigurasi Static Route pada Cisco IOS:

Router(config)# ip route <network-tujuan> <subnet-mask> {<next-hop-ip> | <exit-interface>} [distance]

1. Menggunakan Next-Hop IP (Rekursif):

Router(config)# ip route 192.168.2.0 255.255.255.0 10.0.0.2

Router harus mencari interface keluar (*exit interface*) berdasarkan alamat IP 10.0.0.2 (proses *recursive lookup*).

2. Menggunakan Exit Interface (Directly Attached):

Router(config)# ip route 192.168.2.0 255.255.255.0 Serial0/0/0

Sangat cocok untuk link point-to-point (Serial). Hindari pada interface Ethernet karena router akan membroadcast request ARP untuk setiap host tujuan!

Best Practice (Fully Specified): Cantumkan Exit Interface dan Next-Hop IP sekaligus pada jaringan Ethernet:
Router(config)# ip route 192.168.2.0 255.255.255.0 GigabitEthernet0/1 10.0.0.2
Jelaskan mengapa menggunakan exit interface di interface Ethernet berbahaya: router menganggap seluruh subnet terhubung langsung, sehingga mengirim ARP request untuk setiap paket (menguras memori ARP table).

Default Route

(Gateway of Last Resort / Cisco IOS)

Default Route adalah jenis rute statis khusus yang mencakup seluruh alamat tujuan yang tidak tercantum secara spesifik di routing table.

Router(config)# ip route 0.0.0.0 0.0.0.0 <next-hop-ip / exit-interface>
Makna 0.0.0.0 0.0.0.0:
• IP 0.0.0.0 = Alamat jaringan apa pun.
• Netmask 0.0.0.0 = Nilai prefix 0 bit (cocok dengan alamat IPv4 mana pun).
Fungsi Utama:
Menjadi Gateway of Last Resort pada router cabang/perusahaan untuk meneruskan lalu lintas internet publik menuju router ISP.
Contoh Implementasi:
Router ITERA mengarahkan semua lalu lintas di luar kampus ITERA ke Gateway Telkom / Indosat:
Router-ITERA(config)# ip route 0.0.0.0 0.0.0.0 202.10.1.1
Analogi Default Route: Seperti tanda 'Keluar / All Other Destinations' di persimpangan jalan tol jika kota yang dituju tidak tertulis di plang penunjuk jalan.

Floating Static Route

(Rute Cadangan)

Floating Static Route adalah rute statis yang dikonfigurasikan dengan nilai Administrative Distance (AD) yang sengaja dibuat lebih tinggi daripada rute utama, sehingga berfungsi sebagai jalur cadangan otomatis (*backup link*).

! Jalur Utama (Kabel Fiber Optic 1 Gbps) - AD Default = 1 Router(config)# ip route 192.168.10.0 255.255.255.0 10.1.1.2 ! Jalur Cadangan (Wireless / 4G Modem) - AD Dibuat Menjadi 10 Router(config)# ip route 192.168.10.0 255.255.255.0 10.2.2.2 10
Kondisi Normal (Link Fiber Hidup):
Router memilih jalur AD 1 (10.1.1.2). Jalur AD 10 tidak muncul di routing table ("mengambang/floating").
Kondisi Gangguan (Link Fiber Putus):
Interface 10.1.1.2 down → Rute AD 1 dihapus dari tabel → Rute cadangan AD 10 seketika aktif meneruskan paket!
Floating Static Route adalah trik cerdas yang sangat populer di industri untuk failover link internet tanpa perlu menyalakan protokol dynamic routing yang rumit.

3. Dynamic Routing & RIP (Distance Vector)

Otomasi Pembaruan Rute, Taksonomi IGP/EGP & Protokol Klasik Bellman-Ford

Taksonomi Protokol

Dynamic Routing

Dynamic Routing Protocol memungkinkan router untuk saling bertukar informasi rute secara otomatis dan memperbarui routing table ketika topologi berubah.

Konsep Kunci: Autonomous System (AS) adalah domain jaringan di bawah satu kendali administrasi tunggal (misal: jaringan kampus ITERA, Google, atau Telkom).
Interior Gateway Protocol (IGP)

Routing di dalam satu Autonomous System (AS) / satu organisasi.

  • Distance Vector: RIPv1, RIPv2, EIGRP. Mengetahui arah (vector) dan jarak (distance).
  • Link State: OSPF, IS-IS. Mengetahui peta topologi graf utuh seluruh jaringan.
Exterior Gateway Protocol (EGP)

Routing antar Autonomous System (AS) yang berbeda di internet publik.

  • Path Vector: BGP (Border Gateway Protocol v4).
  • Mempertimbangkan atribut jalur (AS-Path) dan kebijakan bisnis (routing policies).
Ingatkan mahasiswa: AS adalah wilayah kedaulatan satu institusi. IGP adalah lalu lintas internal di dalam satu kampus/perusahaan. EGP (BGP) adalah jaringan jalan raya nasional yang menghubungkan antar kampus/kota di seluruh dunia.

RIP (Routing Information Protocol)

RIP adalah salah satu protokol routing dinamis tertua (didefinisikan dalam RFC 1058).

Karakteristik Kunci RIP:
  • Tipe: IGP Distance Vector (Algoritma Bellman-Ford).
  • Metrik: Hop Count (jumlah router yang dilewati).
  • Batas Hop: Maksimal 15 Hop. Hop ke-16 dianggap Unreachable.
  • Mekanisme Update: Mengirim seluruh isi routing table ke tetangga secara periodik setiap 30 detik via UDP Port 520.
  • Administrative Distance: 120.
Mekanisme Kerja RIP: Pemilihan Jalur Berbasis Hop Count & Kelemahan Bandwidth Blindness
Soroti kelemahan utama RIP: RIP buta terhadap bandwidth. 1 hop link lambat 64 kbps akan dipilih mengalahkan 2 hop link cepat 1 Gbps karena hop count-nya lebih sedikit!

Perbandingan: RIPv1 vs RIPv2

Fitur RIPv1 RIPv2
Tipe Pengalamatan Classful (Hanya Class A, B, C baku) Classless (Mendukung VLSM & CIDR)
Subnet Mask di Update Tidak disertakan Disertakan dalam paket update
Metode Transmisi Update Broadcast ke 255.255.255.255 (Semua host terganggu) Multicast ke alamat khusus 224.0.0.9
Autentikasi Keamanan Tidak ada Mendukung Plain-text & MD5 Hash
Ringkasan Rute Otomatis dipaksa (Auto-summary) Bisa dinonaktifkan (no auto-summary)
! Konfigurasi RIPv2 pada Cisco Router: Router(config)# router rip Router(config-router)# version 2 Router(config-router)# no auto-summary Router(config-router)# network 192.168.1.0 Router(config-router)# network 10.0.0.0
Jelaskan mengapa 'no auto-summary' wajib diketik saat mengaktifkan RIPv2 di Cisco: agar router tidak otomatis meringkas subnet ke batas kelas aslinya.

Count-to-Infinity &

Pencegah Loop RIP

Pada Distance Vector, jika sebuah link mati, router tetangga mungkin tetap saling mengabarkan rute palsu secara berulang sehingga metrik bertambah terus menuju tak terhingga (Count-to-Infinity).

1. Split Horizon
Aturan: Router tidak boleh mengumumkan kembali informasi rute ke interface yang menjadi sumber informasi rute tersebut.
2. Poison Reverse
Ketika rute putus, router sengaja mengiklankan rute tersebut dengan metrik 16 (Infinity) untuk segera membunuh rute mati.
3. Holddown Timer
Router menolak update rute baru untuk durasi tertentu (180 detik) setelah rute mati, guna memberi waktu konvergensi jaringan.
Kesimpulan Limitasi RIP: Karena konvergensinya lambat dan batas 15 hop, RIP saat ini hanya digunakan pada jaringan laboratorium kecil dan telah digantikan oleh OSPF di dunia industri.
Mekanisme Split Horizon dan Poison Reverse adalah materi ujian klasik jaringan komputer. Pastikan mahasiswa paham konsep 'jangan ceritakan kembali gosip ke orang yang memberi tahu gosip tersebut'.

4. OSPF (Open Shortest Path First)

Evolusi dari Distance Vector: Protokol Link-State Berkecepatan Tinggi

Konsep Dasar OSPF (Link-State)

OSPF adalah protokol IGP Link-State standar terbuka (RFC 2328). Hadir menjawab kelemahan Distance Vector: router tidak lagi mengandalkan kabar tetangga, melainkan memetakan graf topologi utuh secara mandiri.

Prinsip Kerja Link-State:
• Kumpulkan status interface → Sebar via LSA (Link-State Advertisement).
• Bangun basis data topologi lengkap: LSDB (Link-State Database).
• Eksekusi Algoritma Dijkstra (SPF) membentuk pohon rute terpendek (Shortest Path Tree).

Administrative Distance: 110 • Transport: IP Protocol 89 (Multicast 224.0.0.5 & 224.0.0.6)

Mekanisme Link-State OSPF: LSA Flooding, Sinkronisasi LSDB, dan Kalkulasi Dijkstra (SPF)
Tegaskan perbedaan filosofis: Pada Distance Vector, router 'mendengar kabar dari tetangga'. Pada Link State, router 'melihat seluruh peta topologi kota sendiri' lalu menghitung rutenya.

Simulasi Interaktif: Algoritma Dijkstra (Link-State)

Relaksasi D(v) = min(D(v), D(u) + c(u,v)) • Stepper graf interaktif • Pohon rute & Forwarding Table
Buka Layar Penuh
Eksplorasi simulator Dijkstra: mahasiswa dapat mencoba rute sendiri, melihat visualisasi air merambat, simulasi langkah demi langkah tabel relaksasi, hingga pembentukan Shortest Path Tree dan Forwarding Table.

Metrik OSPF: Perhitungan Cost

OSPF tidak menggunakan hop count. Metrik OSPF disebut Cost, yang berbanding terbalik dengan bandwidth interface:

Cost = Reference Bandwidth / Interface Bandwidth (bps) Default Reference Bandwidth = 100 Mbps (10^8 bps)
Tipe Interface Bandwidth Formula Cost (Default) Nilai Cost
Serial Cable (T1) 1.544 Mbps $100.000.000 / 1.544.000$ 64
Ethernet 10 Mbps $100.000.000 / 10.000.000$ 10
FastEthernet 100 Mbps $100.000.000 / 100.000.000$ 1
GigabitEthernet 1 Gbps (1000 Mbps) $100.000.000 / 1.000.000.000$ 1 (Membulatkan ke 1)
Catatan Desain Modern: Karena FastEthernet (100M) dan Gigabit (1G) menghasilkan Cost sama (1), pada jaringan modern kita wajib menaikkan Reference Bandwidth:
Router(config-router)# auto-cost reference-bandwidth 10000 (menjadi 10 Gbps).
Bahas jebakan OSPF default: Gigabit dan FastEthernet memiliki cost yang sama yaitu 1 jika reference bandwidth tidak diubah. Tunjukkan perintah auto-cost reference-bandwidth.

Hierarki Multi-Area &

Peran Router OSPF

Konsep Pembagian Area

Membagi jaringan menjadi beberapa area bertujuan untuk membatasi banjir LSA dan memperkecil ukuran LSDB pada router lokal.

  • Area 0 (Backbone Area): Area pusat inti. Seluruh area non-backbone wajib terhubung langsung ke Area 0.
  • Regular Area (Area 1, 2, dst): Mengelompokkan subnet departemen/gedung.
Tipe Peran Router OSPF
  • Internal Router: Semua interfacenya berada di dalam area yang sama.
  • ABR (Area Border Router): Router yang memiliki interface di Area 0 dan interface lain di area non-backbone.
  • ASBR (Autonomous System Boundary Router): Router yang menghubungkan jaringan OSPF ke dunia luar (Static Route, BGP, atau RIP).
! Contoh Konfigurasi OSPF Area 0: Router(config)# router ospf 1 Router(config-router)# router-id 1.1.1.1 Router(config-router)# network 192.168.1.0 0.0.0.255 area 0 Router(config-router)# network 10.0.0.0 0.0.0.3 area 0
Perhatikan wildcard mask pada perintah OSPF: kebalikan dari subnet mask (misal /24 subnet mask 255.255.255.0 menjadi wildcard 0.0.0.255).

Paket OSPF, Adjacency & DR/BDR

5 Tipe Paket OSPF:

  • 1. Hello: Menemukan dan menjaga tetangga (*keepalive* 10s).
  • 2. DBD (Database Description): Ringkasan isi LSDB.
  • 3. LSR (Link State Request): Meminta data LSA spesifik.
  • 4. LSU (Link State Update): Mengirim data LSA lengkap.
  • 5. LSAck: Konfirmasi penerimaan paket LSU.
Tahapan Adjacency:
Down → Init → 2-Way → ExStart → Exchange → Loading → Full

Peran DR & BDR (Multi-Access Ethernet):

Jika 5 router terhubung pada satu switch, akan ada 5 x 4 / 2 = 10 koneksi bertetangga yang memicu ledakan LSA flooding. Solusinya:

• DR (Designated Router): Router pusat pengumpul dan penyebar LSA.
• BDR (Backup DR): Router cadangan jika DR gagal.
• DROther: Router biasa, hanya berteman penuh (*Full Adjacency*) dengan DR dan BDR melalui multicast 224.0.0.6.
Status '2-Way' adalah normal antar sesama DROther. Status 'Full' hanya terjadi antara DROther dengan DR dan BDR.

5. BGP (Border Gateway Protocol)

Dari Jaringan Internal Menuju Perutean Internet Global (Exterior Gateway)

Pengantar BGP: Protokol Penggerak Internet

BGP adalah protokol Exterior Gateway Protocol (EGP) standar internet dunia. Jika OSPF bekerja di dalam kampus (Intra-AS), BGP menghubungkan kampus ke ratusan ribu jaringan internet global (Inter-AS).

Konsep Autonomous System (AS):
Kumpulan jaringan di bawah satu kendali organisasi dengan nomor identitas global unik: ASN (Autonomous System Number) (misal: ITERA, Google, Telkom).
Karakteristik Kunci BGP:
• Tipe: Path-Vector (atribut AS-Path & kebijakan bisnis).
• Transport: TCP Port 179 • Skala: >950.000 rute internet global!
Topologi BGP Inter-AS: Sesi eBGP/iBGP, Pelacakan AS-Path & Kebijakan Bisnis
Jelaskan bahwa BGP tidak mencari jalur tercepat dalam arti milidetik, melainkan jalur yang paling sesuai dengan kebijakan bisnis dan perjanjian kontrak antar penyedia internet.

Dua Mode Operasi: eBGP vs iBGP

eBGP (External BGP)

Sesi BGP yang dibangun antar router yang berada di Autonomous System yang berbeda.

  • Contoh: Koneksi antara Router Edge Telkom (AS 7713) dengan Router Edge Google (AS 15169).
  • Secara default mengasumsikan router terhubung langsung secara fisik (IP TTL = 1).
  • Mengubah nilai attribute Next-Hop ke IP dirinya sendiri saat mengumumkan rute ke AS luar.
  • Administrative Distance: 20.
iBGP (Internal BGP)

Sesi BGP yang dibangun antar router yang berada di dalam Autonomous System yang sama.

  • Berfungsi menyinkronkan rute eksternal yang didapat dari luar ke seluruh router border internal.
  • Tidak memerlukan koneksi fisik langsung (bisa melewati beberapa hop router IGP).
  • Membutuhkan topologi Full-Mesh atau menggunakan Route Reflector untuk mencegah loop internal.
  • Administrative Distance: 200.
Bandingkan AD eBGP (20 - sangat dipercaya karena dari luar langsung) dengan iBGP (200 - kurang dipercaya dibanding OSPF 110).

BGP Path Attributes & Kebijakan Routing (Policy)

BGP tidak menggunakan rumus metrik tunggal seperti RIP atau OSPF. Keputusan rute BGP ditentukan oleh urutan evaluasi Path Attributes:

1. AS-PATH (Mencegah Loop & Menghitung Jarak)
Daftar nomor ASN yang telah dilalui paket.
Contoh: AS-PATH: 15169 7713 23700.
• Jalur dengan AS-PATH lebih pendek lebih diprioritaskan.
• Pencegah Loop: Jika router melihat ASN miliknya sendiri ada di daftar AS-PATH yang diterima, rute seketika dibuang!
2. LOCAL_PREF (Kebijakan Keluar AS)
Nilai lokal di dalam AS untuk menentukan jalur keluar mana yang paling disukai (skala nilai lebih tinggi = lebih disukai). Digunakan untuk memilih ISP utama vs ISP backup.
3. NEXT-HOP
Menentukan alamat IP gateway router perantara menuju AS tetangga berikutnya.
4. MED (Multi-Exit Discriminator)
Saran yang diberikan ke AS tetangga mengenai titik masuk mana yang paling diharapkan ke dalam AS kita (nilai lebih kecil = lebih disukai).
AS-PATH loop prevention adalah mekanisme tercerdas BGP: router AS 100 menolak rute yang mengandung nomor '100' di AS-PATH-nya karena rute tersebut pasti memutar balik.

Panduan Memilih Solusi

Routing yang Tepat

Gunakan Routing Statis
  • Jaringan dengan jumlah router ≤ 3 buah.
  • Koneksi cabang ke kantor pusat (hub-and-spoke stub).
  • Membuat default route keluar ke modem/ISP.
  • Kebutuhan rute cadangan sederhana (floating static).
Gunakan OSPF
  • Jaringan perusahaan, kampus, atau ISP lokal.
  • Topologi memiliki banyak jalur redundansi *mesh*.
  • Perangkat multi-vendor (Cisco, MikroTik, Juniper).
  • Butuh konvergensi cepat tanpa batas 15 hop.
Gunakan BGP
  • Memiliki nomor ASN resmi dan blok IP Public mandiri.
  • Perusahaan terhubung ke 2 ISP berbeda (multi-homing).
  • Penyedia layanan internet (ISP/Telco).
  • Pertukaran rute di Internet Exchange Point (OpenIXP/IIX).
Bimbing mahasiswa mengambil keputusan arsitektural: jangan gunakan BGP untuk jaringan internal kantor kecil, dan jangan gunakan RIP untuk jaringan kampus ITERA.
