1. Pendahuluan Control Plane

Fungsi Network Layer (Data vs Control)

Di Pertemuan 6, kita belajar tentang Data Plane (pengalamatan IP dan subnetting). Sekarang kita masuk ke Control Plane.

Data Plane (Forwarding):
Mekanisme lokal per-router. Memindahkan paket dari input link router ke output link yang tepat berdasarkan Forwarding Table.
Control Plane (Routing):
Logika jaringan secara keseluruhan (network-wide). Menentukan rute/path end-to-end yang akan diambil paket dari sumber ke tujuan. Control Plane lah yang membuat Forwarding Table.
Ingatkan kembali analogi: Forwarding adalah tindakan fisik belok kiri/kanan di persimpangan jalan, sedangkan Routing adalah perencanaan peta rute perjalanan dari kota A ke kota B.

Dua Pendekatan Control Plane

Bagaimana Control Plane diimplementasikan? Ada dua pendekatan utama di internet saat ini:

  1. Kontrol Tradisional (Per-router): Setiap router memiliki agen routing masing-masing (berjalan sendiri-sendiri) yang saling bertukar informasi. Algoritma (seperti OSPF/BGP) dihitung di dalam setiap router.
  2. Software-Defined Networking (SDN): Logika kontrol dipisahkan dari router fisik. Sebuah "otak" terpusat berupa Remote Controller (server) menghitung rute dan meng-install Forwarding Table ke setiap switches.
Per-router adalah model warisan internet sejak awal. SDN adalah inovasi modern di pusat data dan jaringan ISP besar saat ini.

Dua Pendekatan Control Plane (Bagian 2)

Fokus: Kontrol Tradisional (Per-Router Control)

Pada pendekatan tradisional, fungsi Control Plane dan Data Plane menyatu erat di dalam setiap kotak router fisik (arsitektur vertically integrated / monolitik).

📌 Inti Konsep: "Setiap router berpikir sendiri (otak otonom) dan meneruskan paketnya sendiri berdasarkan hasil kalkulasi lokal."
Jelaskan bahwa pendekatan per-router adalah pondasi internet tradisional selama beberapa dekade. Analogi: seperti pengemudi mobil di jalan raya yang masing-masing membawa peta, saling berkomunikasi via radio dengan pengemudi lain, lalu memutuskan sendiri ke mana harus berbelok di setiap persimpangan. Hubungan control plane dan data plane terikat erat (vertically integrated) di sasis perangkat vendor yang sama.

Dua Pendekatan Control Plane (Bagian 3)

Mekanisme Kerja Terdistribusi
  • Komponen Routing Mandiri: Setiap router menjalankan daemon routing (OSPF, RIP, BGP) di prosesor lokal tanpa server sentral.
  • Pertukaran Peer-to-Peer: Router bertukar pesan update/topologi secara berkala dengan router tetangga.
  • Kalkulasi Lokal: Mengeksekusi algoritma (Dijkstra/Bellman-Ford) untuk langsung mengisi Forwarding Table lokal.
Kelebihan & Keterbatasan
  • Kelebihan (Fault-Tolerant): Terdesentralisasi penuh — tidak ada single point of failure. Jaringan otomatis konvergen bila link putus.
  • Keterbatasan (Per-Box Config): Konfigurasi manual satu per satu via CLI/SSH, rawan human error dan lambat diskalakan.
  • Vendor Lock-in: Inovasi lambat karena software dan hardware terikat erat pada vendor proprietary (Cisco, Juniper, dll.).
📌 Inti Konsep: "Setiap router berpikir sendiri (otak otonom) dan meneruskan paketnya sendiri berdasarkan hasil kalkulasi lokal."

Hubungan control plane dan data plane terikat erat (vertically integrated) di sasis perangkat vendor yang sama.

Dua Pendekatan Control Plane (Bagian 4)

Fokus: Software-Defined Networking (SDN)

SDN merevolusi arsitektur jaringan dengan memisahkan (decoupling) logika kendali (Control Plane) dari perangkat keras penerus paket (Data Plane).

Mekanisme Kerja SDN
  • Otak Terpusat (SDN Controller): Server terpusat memiliki pandangan global seluruh topologi dan menghitung semua rute.
  • Perangkat Penerus (Dumb Switches): Switch fisik hanya bertugas memindahkan paket data sesuai instruksi controller.
  • Instalasi Jarak Jauh: Controller memasang flow/forwarding table ke switch via protokol standar (misal OpenFlow).
Kelebihan & Tantangan
  • Kelebihan (Programmable): Jaringan fleksibel, otomatis, dan dapat dikontrol langsung dengan script/API (Python).
  • Manajemen Terpusat: Kebijakan routing, security, dan QoS global dapat diubah seketika dari satu titik kontrol.
  • Tantangan (Resiliensi): Controller harus dibuat redundan (cluster) agar tidak menjadi single point of failure.
⚡ Inti Konsep: "Otak dipusatkan pada server Controller (Software), sementara switch fisik hanya menjadi pelaksana penerus paket (Hardware)."
SDN menjadi standar di arsitektur data center modern (seperti Google, AWS, Microsoft) karena memungkinkan otomatisasi ribuan server secara dinamis.

Ilustrasi: Per-Router vs SDN

Kontrol Tradisional (Per-Router)
  • Arsitektur Monolitik: Control Plane (Algoritma OSPF/BGP di CPU) dan Data Plane (FIB) menyatu di setiap router fisik.
  • Koordinasi Peer-to-Peer: Router saling bertukar pesan rute dengan tetangga untuk menghitung jalur terpendek secara mandiri.
  • Karakteristik: Desentralisasi penuh, toleran terhadap kegagalan, namun memerlukan konfigurasi manual per-perangkat.
Software-Defined Networking (SDN)
  • Pemisahan (Decoupling): Otak kendali dipusatkan pada SDN Controller, terpisah dari perangkat keras penerus data.
  • Instalasi Jarak Jauh: Controller menghitung rute global dan memasang Flow Table via protokol standar (OpenFlow).
  • Karakteristik: Programmable via API/software, manajemen kebijakan terpusat, dan switch fisik beroperasi secara sederhana.
Bandingkan kedua arsitektur secara visual: Pada Per-Router (kiri), setiap router memiliki otak dan otot sendiri serta berkoordinasi peer-to-peer. Pada SDN (kanan), otak dipisahkan dan dipusatkan pada server Controller yang menginstruksikan switch-switch di bawahnya via OpenFlow.

2. Algoritma Routing

Tujuan & Abstraksi Graf (Graph)

Tujuan Routing: Menemukan jalur (rute) "terbaik" dari sumber ke tujuan. "Terbaik" bisa berarti rute dengan biaya terkecil (least cost), tercepat, atau paling tidak macet (least congested).

Abstraksi Graf: G = (N, E)

  • N (Nodes): Kumpulan router (misal: {u, v, w, x, y, z}).
  • E (Edges): Kumpulan link fisik yang menghubungkan router.
  • c(x, y): Biaya link (Link Cost) dari router x ke y. Nilainya bisa 1, atau berbasis kapasitas bandwidth, delay, dll. Jika tidak terhubung langsung, biayanya adalah ∞ (tak terhingga).
Dalam teori graf jaringan komputer, setiap router direpresentasikan sebagai simpul (node) dan setiap kabel penghubung sebagai sisi (edge).

Klasifikasi Algoritma Routing

Secara umum, algoritma routing dibagi berdasarkan seberapa banyak informasi yang dimiliki oleh sebuah router sebelum menghitung rute:

1. Link-State (Algoritma Global)
Seluruh router memiliki informasi lengkap tentang topologi dan biaya link seluruh jaringan (Global). Diperoleh dengan cara melakukan "Link State Broadcast" ke semua router. Contoh algoritmanya: Algoritma Dijkstra.
2. Distance Vector (Algoritma Desentralisasi)
Router di awal hanya tahu biaya link ke tetangga terdekatnya. Router kemudian secara iteratif bertukar "vektor jarak" dengan tetangganya hingga rute terbaik ditemukan. Contoh algoritmanya: Algoritma Bellman-Ford.

Algoritma Link-State: Dijkstra

Tujuan: Menghitung biaya terpendek (Least-cost path) dari satu titik sumber (source) ke semua titik lain di dalam jaringan.

Rumus Iterasi Dijkstra (Relaxation):
D(v) = min( D(v), D(w) + c(w,v) )
  • D(v): Estimasi jarak terpendek dari sumber ke node v.
  • c(w,v): Biaya fisik dari tetangga w ke v.
  • Intinya: "Apakah biaya lama ke V lebih murah, ATAU lewat W ke V lebih murah?"

Penerapan di Lapisan Network: Digunakan oleh protokol OSPF. Setiap router menjalankan Dijkstra secara mandiri setelah menerima gambaran topologi utuh dari router lain, untuk mengisi Forwarding Table-nya.

Jelaskan bahwa pada setiap iterasi kita selalu memilih node dengan estimasi terkecil yang belum masuk ke himpunan N', lalu memperbarui estimasi tetangga-tetangganya.

Algoritma Distance Vector: Bellman-Ford

Berkebalikan dengan Link-State, Distance Vector tidak menyebarkan topologi utuh. Router hanya bertukar tabel estimasi jarak dengan tetangga sebelahnya saja.

Persamaan Bellman-Ford (BF):
Dx(y) = minv { c(x,v) + Dv(y) }
  • Dx(y): Biaya minimum (estimasi) dari node x ke y.
  • minv: Coba lewati setiap tetangga (v).
  • Pilih tetangga (v) yang memberikan akumulasi cost (x ke v) + cost minimum (v ke y) yang paling kecil.

Penerapan: Protokol RIP (Routing Information Protocol) dan sebagian konsep dalam BGP (Path Vector). Algoritma ini bersifat asinkron, iteratif, dan terdesentralisasi.

Distance Vector hemat overhead broadcast, namun rentan mengalami fenomena 'Count to Infinity' jika terjadi link failure.

3. Protokol Routing di Internet

Routing Hierarkis: Intra-AS

Karena ukuran Internet sangat masif (ratusan juta router), tidak mungkin menyimpan seluruh rute di satu tabel global. Internet dibagi menjadi blok-blok besar otonom yang disebut Autonomous System (AS) / Domain.

Intra-AS (Interior Gateway Protocol)
  • Routing di dalam satu domain/ISP yang sama (kendali administratif tunggal).
  • Fokus Utama: Optimasi performa teknis (mencari rute dengan biaya minimum / cost terkecil).
  • Otonomi Penuh: Administrator jaringan bebas memilih metrik dan algoritma tanpa intervensi pihak luar.
  • Protokol Populer:
    • OSPF (Open Shortest Path First) — Link-State (Dijkstra)
    • IS-IS (Intermediate System to Intermediate System)
    • RIP (Routing Information Protocol) — Distance Vector
Topologi & Alur Intra-AS

Router internal berkoordinasi via OSPF untuk menghitung rute biaya terpendek (Least Cost) menuju Router Gerbang.

📌 Inti Konsep: Intra-AS mengutamakan efisiensi performa internal organisasi, di mana seluruh router internal berada di bawah kebijakan satu otoritas administratif.
Analogikan Intra-AS seperti navigasi lalu lintas di dalam komplek kampus atau satu kota otonom. Seluruh persimpangan (router internal) bekerja sama mencari jalur paling cepat menuju gerbang keluar (Gateway Router) menggunakan protokol interior seperti OSPF.

Routing Hierarkis: Inter-AS

Karena ukuran Internet sangat masif, routing antar organisasi yang independen membutuhkan koordinasi lintas domain yang disebut Inter-AS (Exterior Gateway Routing).

Inter-AS (Exterior Gateway Protocol)
  • Routing antar Autonomous System / ISP yang berbeda di seluruh dunia.
  • Fokus Kebijakan (Policy): Dipandu oleh kesepakatan bisnis, privasi, dan regulasi ekonomi, bukan sekadar jalur fisik terpendek.
  • Dua Peran Sesi BGP:
    • eBGP: Bertukar informasi rute jangkauan dengan AS tetangga.
    • iBGP: Menyebarkan rute eksternal ke router internal di dalam AS.
  • Standar Global De Facto: BGP (Border Gateway Protocol) — "lem perekat keutuhan internet global".
Topologi & Sesi Inter-AS (BGP)

Router Gerbang menghubungkan AS 1, AS 2, dan AS 3 melalui sesi eBGP dengan penegakan kebijakan bisnis (Policy Routing).

📌 Inti Konsep: Inter-AS mengutamakan penegakan kebijakan bisnis (policy) dan kontrol privasi antar penyedia layanan, sehingga rute yang dipilih adalah rute yang disepakati secara komersial.
Jelaskan bahwa jika Intra-AS adalah navigasi internal satu kota, maka Inter-AS adalah sistem diplomasi dan perjanjian penerbangan antar negara. BGP memungkinkan ISP menentukan siapa yang boleh melintas dan jalur mana yang diumumkan ke dunia luar.

4. Protokol Bantuan & Manajemen

Apa itu ICMP?

ICMP (Internet Control Message Protocol) digunakan oleh perangkat jaringan untuk saling mengirimkan pesan kesalahan (error reporting) dan informasi operasional (diagnostik).

  • Berada di atas (berjalan menggunakan) protokol IP. Datagram IP berisi paket ICMP.
  • Format Pesan: Memiliki kolom Type (Tipe) dan Code (Kode) untuk mengidentifikasi pesan.
ICMP Tipe & Kode Umum Fungsi
Type 0 Code 0 Echo Reply (Balasan Ping Berhasil)
Type 8 Code 0 Echo Request (Request Pengujian Ping)
Type 3 Code 3 Destination Port Unreachable (Port aplikasi tujuan tertutup)
Type 11 Code 0 TTL Expired (Masa hidup paket habis, kunci Traceroute!)

Penerapan ICMP: Ping

Program: PING

Menguji keterjangkauan host tujuan dan mengukur waktu latensi bolak-balik (Round-Trip Time).

  • Echo Request (Type 8): Klien mengirim paket ICMP Type 8 ke alamat IP tujuan.
  • Echo Reply (Type 0): Jika host target aktif dan tidak memfilter ICMP, ia merespons dengan paket Type 0.
  • Metrik Kunci:
    • RTT (Latency): Waktu tempuh paket bolak-balik (ms).
    • Packet Loss: Persentase paket yang gagal kembali (drop/timeout).
Ilustrasi Alur Ping

Pengirim mengirim ICMP Type 8 (Request) dan menerima ICMP Type 0 (Reply) untuk menghitung RTT.

📌 Inti Konsep: Ping adalah alat diagnostik tercepat untuk memverifikasi apakah host tujuan aktif pada Network Layer (Layer 3) dan mengukur latensi end-to-end.
Jelaskan bahwa jika ping menampilkan Request Timed Out (RTO), kemungkinannya adalah host mati, kabel putus, atau firewall tujuan memblokir paket ICMP Type 8.

Penerapan ICMP: Traceroute

Program: TRACEROUTE (Tracert)

Menelusuri seluruh rute hop-by-hop dari host sumber menuju server tujuan.

  • Inkrementasi TTL: Pengirim sengaja mengirim paket probe berurutan dengan TTL = 1, TTL = 2, TTL = 3, dst.
  • Pesan TTL Expired (Type 11): Router di hop ke-n mengurangi TTL menjadi 0, men-drop paket, lalu membalas dengan ICMP Type 11 (Time Exceeded).
  • Pencatatan Hop: Alamat IP pengirim pesan balasan dicatat sebagai identitas router hop tersebut bersama waktu RTT-nya.
  • Kondisi Berhenti: Saat mencapai host tujuan, server membalas dengan ICMP Port Unreachable (Type 3) atau Echo Reply (Type 0).
Ilustrasi Alur Traceroute

Pemanfaatan cerdas inkrementasi TTL bertahap & pesan ICMP Type 11 untuk mengungkap rute perantara.

📌 Inti Konsep: Traceroute secara kreatif memanfaatkan batas masa hidup paket (TTL) untuk memancing router di sepanjang jalur mengirimkan pesan kesalahan ICMP Type 11 sebagai penanda jejak.
Jelaskan kecerdasan mekanisme ini: Traceroute tidak memerlukan protokol penelusuran rute baru, melainkan memanfaatkan secara cerdas perilaku standar IP saat TTL habis (ICMP Type 11) untuk mengungkap topologi perantara satu per satu.

Network Management (SNMP)

Di jaringan raksasa (Enterprise), admin tidak mungkin login (SSH) ke ratusan router satu per satu setiap detik untuk melihat status port. Kita butuh Network Management.

Komponen SNMP
  • Managing Server (Manager): Aplikasi sentral (misal: Cacti, Zabbix, Prometheus) yang bertugas menarik data.
  • Managed Device (Agent): Router/Switch yang menjalankan aplikasi agen SNMP.
  • MIB (Management Information Base): Struktur database hirarkis di dalam router (cth: OID untuk statistik trafik port).
Metode Pesan SNMP
  • GetRequest: Manager meminta data spesifik (misal: utilisasi CPU router).
  • SetRequest: Manager mengubah nilai konfigurasi di Router.
  • Trap: Router melapor mandiri ke Manager saat ada kondisi bahaya (misal: port down / kabel dicabut).

Evolusi Manajemen: NETCONF & YANG

SNMP bagus untuk membaca data (statistik), namun sangat rumit dan jarang dipakai untuk konfigurasi jaringan massal (otomasi). Internet modern menggunakan pendekatan baru:

  • NETCONF: Protokol berbasis RPC (Remote Procedure Call) yang aman (via SSH/TLS) dan memakai format pesan XML. Bisa memanipulasi konfigurasi, melakukan rollback, dan transaksi (atomic commits) pada banyak perangkat sekaligus.
  • YANG: Bahasa pemodelan data (Data Modeling Language) yang dipakai oleh NETCONF. Ia mendeskripsikan tipe data, batasan (constraints), dan struktur konfigurasi perangkat layaknya sebuah skema database.
NETCONF dan YANG adalah tulang punggung dari SDN (Software-Defined Networking) modern, karena sangat bersahabat dengan bot dan script otomasi python/Ansible.

Rangkuman Pertemuan 7

Control Plane & Routing

  • Pendekatan: Per-router (mandiri, tradisional) vs SDN (terpusat logis).
  • Dijkstra (Link-State): Info topologi global. Menghitung rute terpendek dengan relaksasi D(v) = min(D(v), D(w)+c) (Contoh: OSPF).
  • Bellman-Ford (Dist-Vector): Bertukar info vektor jarak lokal dengan tetangga. Menghitung biaya minimum iteratif (Contoh: RIP, BGP).

Manajemen & Protokol Pendukung

  • ICMP: Untuk pelaporan error & pengujian jaringan (Ping, Traceroute via TTL).
  • SNMP: Mengecek statistik router menggunakan MIB, Get, Set, dan Trap.
  • NETCONF & YANG: Otomasi konfigurasi jaringan berbasis XML/SSH untuk era SDN modern.
