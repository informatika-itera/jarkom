1. Fondasi & Konsep Socket API

Abstraksi Soket, Paradigma Client–Server, Pemetaan IP & Port, dan Karakteristik Layanan

Bagian pertama membahas konsep dasar soket sebagai antarmuka antara aplikasi dan sistem operasi, serta paradigma arsitektur jaringan.

Paradigma Layanan: Client–Server

Hampir seluruh layanan internet dikonstruksi menggunakan paradigma Client–Server:

  • Server: Host yang selalu menyala (always-on), memiliki IP permanen, dan menjalankan proses yang terus mendengarkan (listening) pada port tertentu.
  • Client: Host yang berkomunikasi dengan server secara dinamis (on-demand), dapat menggunakan IP dinamis, dan tidak berkomunikasi langsung antar-klien.
Asimetri Komunikasi: Server bersifat pasif menunggu ketukan tamu, sedangkan Client bersifat aktif memprakarsai koneksi.
Model Asimetris Komunikasi Client–Server dan Isolasi Antar-Klien

Abstraksi Socket: Pintu Gerbang ke Jaringan

Definisi: Socket adalah Pintu (Doorway) atau titik akhir (endpoint) komunikasi dua arah antara proses aplikasi dan stack protokol jaringan OS.

Batas Kendali Arsitektur (Boundary of Control):

  • Di Atas Socket (User Space): Dikendalikan penuh oleh App Developer. Bebas memilih bahasa (Python, C, Java), format pesan, dan logika aplikasi.
  • Di Bawah Socket (Kernel Space): Dikendalikan sepenuhnya oleh Sistem Operasi. Mengelola buffer transmisi, nomor sequence, checksum, dan kartu jaringan (NIC).
Konsep Pintu Gerbang (Doorway) dan Batas Kendali User Space vs Kernel Space

Dua Tipe Socket Transport

Sistem Operasi menyediakan dua jenis transport service utama yang menentukan tipe Socket:

  • UDP (User Datagram Protocol) → SOCK_DGRAM:
    • Layanan unreliable, berbasis Datagram independen.
    • Cepat dan ringan, tanpa overhead handshaking.
    • Tidak ada jaminan urutan dan keutuhan paket.
  • TCP (Transmission Control Protocol) → SOCK_STREAM:
    • Layanan reliable, berbasis aliran bita (byte-stream).
    • Menjamin paket sampai secara utuh, berurutan, dan tanpa duplikasi.
    • Memerlukan proses koneksi (3-way handshake).
Komparasi Karakteristik Layanan Socket TCP (Stream) vs Socket UDP (Datagram)

Spesifikasi Aplikasi Lab: Uppercase Server

Untuk menguji kedua jenis soket, kita membangun aplikasi konversi huruf kapital:

  1. Client: Membaca satu baris kalimat huruf kecil dari keyboard.
  2. Client → Server: Mengirimkan bita teks melalui soket jaringan.
  3. Server: Menerima data dan mengonversinya menjadi HURUF KAPITAL.
  4. Server → Client: Mengirimkan balik bita hasil modifikasi ke Client.
  5. Client: Menerima balasan dari soket dan mencetaknya ke layar terminal.
Alur Sekuensial Permintaan–Balasan (Request–Response) Klien–Server

2. Pemrograman Socket UDP & Simulasi

Komunikasi Connectionless, Format Datagram, Siklus Hidup API, dan Live Simulasi Dual-Terminal

Bagian kedua membedah pemrograman soket berbasis UDP: sifat tanpa koneksi, implementasi kode Python, dan demonstrasi terminal langsung.

Socket Programming dengan UDP (Connectionless)

Karakteristik fundamental soket UDP:

  • No Handshake: Tidak ada sesi koneksi yang dibangun sebelum transmisi data. Pengirim langsung menembakkan paket datagram.
  • Eksplisit Address Tagging: Setiap paket datagram wajib ditempeli pasangan alamat target: (IP Address, Port Number).
  • Ekstraksi Alamat Pengirim: Saat menerima paket via recvfrom(), sistem mengembalikan tuple (data, clientAddress) sehingga server tahu ke mana harus membalas.
  • Resiko: Paket dapat hilang di rute jaringan (packet loss) tanpa notifikasi error di sisi pengirim.
Mekanisme Datagram Mandiri, Tagging Alamat Eksplisit, dan Ekstraksi recvfrom()

Bedah Kode: UDP Server (Python 3)

Arsitektur Eksekusi UDPServer.py:

  1. Inisiasi Soket: socket(AF_INET, SOCK_DGRAM) membuat soket datagram IPv4 di User Space.
  2. Binding Port: serverSocket.bind(('', 12000)) mengikat soket ke port 12000 pada seluruh antarmuka lokal.
  3. Infinite Service Loop: while True: menjaga proses server selalu aktif menyambut datagram dari klien mana pun.
  4. Penerimaan Datagram: recvfrom(2048) membaca muatan bita sekaligus tuple clientAddress.
  5. Pemrosesan & Balasan: Data didekode, diubah ke huruf kapital, lalu ditembakkan balik via sendto().
Kunci Arsitektur UDP: Server UDP tidak memerlukan panggilan listen() maupun accept(). Satu serverSocket tunggal melayani seluruh klien secara langsung. 
from socket import *

serverPort = 12000

# 1. Membuat UDP Socket (AF_INET = IPv4, SOCK_DGRAM = UDP)
serverSocket = socket(AF_INET, SOCK_DGRAM)

# 2. Mengikat (Bind) soket ke port lokal 12000
serverSocket.bind(('', serverPort))
print('Server UDP siap menerima paket...')

# 3. Infinite loop untuk terus melayani datagram yang masuk
while True:
    # 4. recvfrom membaca bita payload & tuple alamat pengirim
    message, clientAddress = serverSocket.recvfrom(2048)
    
    # 5. Konversi bytes ke string, ubah ke kapital
    modifiedMessage = message.decode().upper()
    
    # 6. Mengirim balik bita balasan langsung ke klien pengirim
    serverSocket.sendto(modifiedMessage.encode(), clientAddress)
Perhatikan bahwa server UDP tidak memiliki listening queue dan tidak mencetak socket baru. Satu serverSocket melayani seluruh pengirim.

Bedah Kode: UDP Client (Python 3)

Arsitektur Eksekusi UDPClient.py:

  1. Inisiasi Soket: clientSocket = socket(AF_INET, SOCK_DGRAM). Kernel otomatis mengalokasikan port efemeral dinamis.
  2. Serialisasi Teks: message.encode() mengubah string keyboard menjadi bita mentah (raw bytes).
  3. Explicit Addressing: sendto(..., (serverName, serverPort)) menembakkan datagram langsung ke target (0 RTT).
  4. Penerimaan Balasan: recvfrom(2048) membaca bita balasan dari server ke dalam buffer.
  5. Penutupan: clientSocket.close() melepaskan sumber daya soket ke sistem operasi.
⚠️ Titik Kritis Blocking I/O: Panggilan recvfrom(2048) bersifat blocking default. Jika paket hilang di rute jaringan, klien akan terkunci (freeze) selamanya. Masalah ini akan kita pecahkan dengan settimeout() pada Bagian 4. 
from socket import *

serverName = '127.0.0.1'  # atau hostname/IP server tujuan
serverPort = 12000

# 1. Membuat socket UDP klien
clientSocket = socket(AF_INET, SOCK_DGRAM)

message = input('Ketik kalimat huruf kecil: ')

# 2. Mengirim data mentah beserta tuple tujuan (IP, Port)
clientSocket.sendto(message.encode(), (serverName, serverPort))

# 3. Menunggu balasan (buffer 2048 bytes - BLOCKING!)
modifiedMessage, serverAddress = clientSocket.recvfrom(2048)
print('Balasan Server:', modifiedMessage.decode())

# 4. Tutup socket
clientSocket.close()
Tunjukkan bahwa clientSocket tidak melakukan bind() secara eksplisit karena OS otomatis mengalokasikan ephemeral port saat sendto pertama dieksekusi.

3. Pemrograman Socket TCP & Handshake

Reliable Byte-Stream, 3-Way Handshake, Welcoming vs Connection Socket, dan Live Simulasi Dual-Terminal

Bagian ketiga membahas TCP yang berorientasi koneksi: jabat tangan 3 arah, pemisahan soket di sisi server, dan simulasi transmisi aliran bita.

Socket Programming dengan TCP (Connection-Oriented)

TCP bekerja bagaikan sambungan telepon: koneksi harus dibangun sebelum komunikasi berlangsung.

  • 3-Way Handshake: Klien mengontak Server via connect(), OS mempertukarkan paket kontrol (SYN, SYN-ACK, ACK) untuk menyinkronkan nomor sequence.
  • Virtual Pipe (Pipa Virtual): Setelah tersambung, terbentuk saluran kontinu byte-stream. Data mengalir terurut, reliabel, dan tanpa kehilangan bita.
  • Stream Abstraction: Berbeda dengan datagram UDP, pemanggilan send() tidak perlu menyertakan tuple IP/Port lagi karena tujuan sudah melekat pada pipa.
Fase 3-Way Handshake, Pipa Virtual Byte-Stream, dan Implicit Addressing

Konsep Welcoming vs Connection Socket

Perbedaan paling krusial di sisi Server TCP adalah keberadaan dua jenis soket:

  • 1. Welcoming Socket (serverSocket):
    • Terikat pada port utama (contoh: port 12000).
    • Tugasnya HANYA menyambut ketukan tamu baru via listen() dan accept().
    • Tidak pernah dipakai untuk membaca atau menulis data aplikasi!
  • 2. Connection Socket (connectionSocket):
    • Dicetak baru oleh OS setiap kali accept() berhasil.
    • Didedikasikan privat 1-on-1 dengan klien spesifik tersebut.
    • Setelah transaksi selesai, soket ini ditutup, sementara Welcoming Socket tetap menyala.

Bedah Kode: TCP Server (Python 3)

Arsitektur Eksekusi TCPServer.py:

  1. Welcoming Socket: socket(AF_INET, SOCK_STREAM) membuat soket penyambut TCP di port 12000.
  2. Mode Listening: serverSocket.listen(1) membuka antrian masuk permohonan koneksi.
  3. Handshake & Forking: connectionSocket, addr = serverSocket.accept() menahan proses (blocking) hingga 3-way handshake selesai, lalu menghasilkan soket baru khusus klien tersebut.
  4. Stream Transmisi: connectionSocket.recv(1024) dan send() membaca/menulis langsung dari pipa virtual tanpa alamat IP.
  5. Penutupan Sesi: connectionSocket.close() menutup sesi klien, sementara serverSocket tetap aktif menyambut klien lain.
Kunci Arsitektur TCP: Jangan pernah menutup serverSocket.close() di dalam perulangan while True! 
from socket import *

serverPort = 12000

# 1. Membuat Welcoming Socket (SOCK_STREAM = TCP)
serverSocket = socket(AF_INET, SOCK_STREAM)
serverSocket.bind(('', serverPort))

# 2. Mulai mendengarkan antrian koneksi masuk
serverSocket.listen(1)
print('Server TCP siap menerima koneksi...')

while True:
    # 3. Blocking di accept(). Saat ada klien masuk,
    #    OS menghasilkan connectionSocket BARU khusus klien ini
    connectionSocket, addr = serverSocket.accept()
    
    # 4. Menerima data stream langsung dari pipa virtual
    sentence = connectionSocket.recv(1024).decode()
    capitalizedSentence = sentence.upper()
    
    # 5. Mengirim balasan dan menutup connectionSocket
    connectionSocket.send(capitalizedSentence.encode())
    connectionSocket.close()  # Sesi klien ini selesai
    # (serverSocket welcoming socket TIDAK DITUTUP!)
Tunjukkan perbedaan serverSocket.close() vs connectionSocket.close(). Ini pertanyaan jebakan ujian yang sangat sering muncul.

Bedah Kode: TCP Client (Python 3)

Arsitektur Eksekusi TCPClient.py:

  1. Inisiasi Soket: clientSocket = socket(AF_INET, SOCK_STREAM) membuat soket stream TCP.
  2. 3-Way Handshake: clientSocket.connect((serverName, serverPort)) memicu pertukaran segmen SYN → SYN-ACK → ACK. Terhubung sebelum data pertama dikirim.
  3. Implicit Stream: clientSocket.send(sentence.encode()) mengalirkan bita ke pipa tanpa parameter IP/Port lagi.
  4. Penerimaan Stream: clientSocket.recv(1024) membaca bita balasan dari pipa virtual (blocking).
  5. Penutupan Teratur: clientSocket.close() mengirim segmen FIN untuk membongkar koneksi.
⚠️ Titik Kritis Blocking I/O: Baik connect() maupun recv() adalah operasi blocking. Jika server hang di tengah transmisi stream, klien terkunci. Solusinya dibahas tuntas pada Slide 21 dengan settimeout(). 
from socket import *

serverName = '127.0.0.1'
serverPort = 12000

# 1. Membuat socket TCP klien (SOCK_STREAM)
clientSocket = socket(AF_INET, SOCK_STREAM)

# 2. Inisiasi koneksi 3-way handshake ke server (BLOCKING!)
clientSocket.connect((serverName, serverPort))

sentence = input('Ketik kalimat huruf kecil: ')

# 3. Mengalirkan data ke pipa tanpa target IP lagi
clientSocket.send(sentence.encode())

# 4. Menerima bita stream balasan (BLOCKING!)
modifiedSentence = clientSocket.recv(1024)
print('Balasan Server:', modifiedSentence.decode())

# 5. Menutup koneksi TCP (FIN-ACK handshake)
clientSocket.close()
Tekankan bahwa connect() wajib dijalankan sebelum send(). Jika server belum siap, connect() akan memicu ConnectionRefusedError.

4. Keandalan, Timeout & Troubleshooting

Penanganan Blocking I/O, Penerapan settimeout(), Kasus The Shepherd Boy, Komparasi API & Best Practices

Bagian keempat fokus pada aspek keandalan tingkat lanjut: mencegah server hang dengan timeout, menangani eksepsi, dan mengatasi kendala umum pemrograman soket.

Mitigasi Blocking I/O dengan Timeout & Exception

Korelasi dengan Kode Slide Sebelumnya:

Pada UDPClient.py (Slide 12) dan TCPClient.py (Slide 18), pemanggilan fungsi membaca seperti recvfrom() dan recv() berjalan secara blocking default. Jika paket hilang atau server hang, program klien membeku (freeze) tanpa batas waktu.

Solusi: clientSocket.settimeout(detik)

  • Memasang timer batas waktu tunggu maksimal pada soket (baik UDP maupun TCP).
  • Jika dalam kurun waktu tersebut tidak ada data yang masuk, Python membangkitkan interupsi socket.timeout.
  • Wajib dibungkus dalam blok proteksi try ... except agar aplikasi dapat melakukan mitigasi secara anggun (graceful handling) tanpa mengalami crash.
Universal: Pola proteksi settimeout() dan try...except ini berlaku identik untuk mengamankan UDPClient.py maupun TCPClient.py. 
import socket

# Mengamankan TCPClient dari Slide 18 dengan Timeout:
clientSocket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# 1. Pasang batas waktu tunggu maksimal 10 detik
clientSocket.settimeout(10.0)

try:
    # 2. Inisiasi koneksi ke server
    clientSocket.connect(('127.0.0.1', 12000))
    clientSocket.send(b"Hello Server")
    
    # 3. Menerima balasan (terlindungi batas 10 detik)
    data = clientSocket.recv(1024)
    print("Diterima:", data.decode())
    
except socket.timeout:
    print("Error: Batas waktu 10 detik habis! Server tidak merespons.")
    
except socket.error as e:
    print("Kesalahan jaringan / koneksi:", str(e))
    
finally:
    # 4. Pastikan soket selalu ditutup dengan aman
    clientSocket.close()
Tunjukkan bahwa tanpa settimeout(), jika server tidak merespons maka baris recv() akan hang selamanya dan mematikan antarmuka aplikasi.

Contoh Kasus TCP Server Timeout (The Shepherd Boy)

Studi Kasus Keamanan Jaringan: Mencegah serangan Idle Connection / Slowloris di mana Klien iseng terhubung ke Server tetapi tidak pernah mengirim data.

Analoginya:

  • Anak gembala (Klien) terkoneksi ke Warga Desa (Server), namun diam saja.
  • Server memasang timer connectionSocket.settimeout(10).
  • Jika dalam 10 detik anak gembala tidak melapor lokasi serigala, server mencatat 1 poin keisengan (counter bertambah).
  • Setelah 3 kali timeout berturut-turut, Server memutus sambungan secara permanen.

Implementasi The Shepherd Boy (TCPServer)

from socket import *
serverSocket = socket(AF_INET, SOCK_STREAM)
serverSocket.bind(('', 12000))
serverSocket.listen(1)

counter = 0
while counter < 3:
    connectionSocket, addr = serverSocket.accept()
    
    # Memasang batas waktu 10 detik khusus untuk koneksi anak gembala ini
    connectionSocket.settimeout(10.0)
    
    try:
        wolf_location = connectionSocket.recv(1024).decode()
        send_hunter(wolf_location) # Dispatch bantuan
        connectionSocket.send('hunter sent'.encode())
        
    except timeout:
        # Menangkap waktu habis saat anak gembala diam saja
        counter += 1
        print(f"Bocah iseng ketahuan! Peringatan ke-{counter}/3")
        
    finally:
        connectionSocket.close()

print("Batas toleransi 3x habis! Server menolak anak gembala permanen.")

Komparasi Komprehensif: TCP vs UDP Socket API

Dimensi Analisis UDP Socket (Datagram) TCP Socket (Stream)
Konstanta Tipe AF_INET, SOCK_DGRAM AF_INET, SOCK_STREAM
Inisiasi Sesi Tanpa koneksi (No handshake) 3-Way Handshake via connect()
Soket di Sisi Server 1 Soket Tunggal untuk semua pengirim 2 Jenis Soket (1 Welcoming + 1 Dedicated Connection Socket)
Pengiriman Data sendto(bytes, (ip, port)) send(bytes) (Pipa virtual terbentuk)
Penerimaan Data recvfrom(bufsize) → (data, addr) recv(bufsize) → data
Integritas & Urutan Bisa hilang, rusak, atau teracak (unreliable) Terurut rapi, retransmisi otomatis (reliable)
Batas Pesan (Framing) Mempertahankan batas datagram Aliran bita berkesinambungan (stream of bytes)
Kasus Penggunaan Ideal DNS, VoIP, Live Video, Game Online FPS HTTP/HTTPS, File Transfer (FTP), E-mail, SSH

Panduan Praktis & Troubleshooting Pemrograman Socket

Address Already in Use

Errno 48 Terjadi saat server dimatikan dan langsung dinyalakan kembali, port masih di-hold dalam status TIME_WAIT oleh kernel OS.

Solusi Wajib:

s.setsockopt(
  SOL_SOCKET, 
  SO_REUSEADDR, 1
)
Bytes vs String (Python 3)

TypeError Soket jaringan mentransmisikan bita mentah (raw bytes), bukan string teks Unicode Python.

Solusi Wajib:

  • Saat Mengirim:
    pesan.encode('utf-8')
  • Saat Menerima:
    data.decode('utf-8')
Port Privilege & Firewall

Best Practice Pemilihan nomor port pengujian:

  • 0 – 1023: Well-known ports (butuh hak akses root/Administrator).
  • 1024 – 65535: Port bebas (Registered & Dynamic). Gunakan angka di atas 1024 (contoh: 12000).
  • Pastikan firewall lokal mengizinkan inbound traffic.

Rangkuman Modul Socket Programming

Setelah menguasai Socket, kita telah menutup bab Application Layer dengan sempurna. Hal esensial yang kita pelajari:

  • Paradigma Request/Reply: Klien menginisiasi permintaan layanan, Server merespons dan mengeksekusi logika komputasi.
  • Format Pesan: Jaringan hanya mentransmisikan urutan bita (raw bytes stream / datagram), aplikasi bertanggung jawab melakukan serialisasi/deserialisasi.
  • Filosofi Arsitektur Internet: Jaringan inti (core routers) dibuat sesederhana mungkin, sedangkan seluruh kompleksitas dan kecerdasan komputasi diletakkan di tepi jaringan (complexity at the network edge).
